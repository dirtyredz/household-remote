# Launch app buttons by Samsung app ID; remove calibrated sequences

Owner decision 2026-10-28: replace the per-TV calibrated key sequences with direct app launch by ID, and remove the Calibrate flow and the sequence code (ShortcutProfile/ShortcutStore/ShortcutTextCodec, CalibrationDialog). Record the reversal in docs/DECISIONS.md.

Evidence (read-only GET http://<tv>:8001/api/v2/applications/<id>, 2026-10-28): the household TVs report the apps installed under these IDs: Netflix 3201907018807, Prime Video 3201910019365, Disney+ 3201901017640, Plex 3201512006963. The older IDs 11101200001 and 3201512006785 return 404. With owner permission on 2026-10-28, a plain REST POST to the Netflix application endpoint returned HTTP 200 true and changed Netflix from visible:false to visible:true. No TV addresses or identifying model details are recorded in this public repository.

Design: REST POST /api/v2/applications/<id> is primary because it is proven on the affected TV. The existing paired-websocket payload is structurally correct (method ms.channel.emit, event ed.apps.launch, to host, data {appId, action_type: DEEP_LINK}) but is only the fallback after a failed REST request. Grey out a button only when the current usable session reports that the app is not installed (404); unknown, timeout and stale statuses stay usable. A launch requires a usable session, is never held during recovery and is never replayed. No physical launch occurs during automated verification; the owner checks each button on the phone.

Implementation: AppInstallClient uses its private-IPv4-only, three-second, no-redirect, no-HTTP-retry client to POST an empty body to :8001/api/v2/applications/<id>. A non-2xx reply or I/O failure invokes KeyDispatcher.launch once as the websocket fallback. Lifecycle stop and TV selection cancel pending launch work; the fallback also rechecks that the same TV session is usable. Install results are cleared before every new-session probe so an old 404 cannot leave a button disabled. AppLaunchTest retains the exact fallback JSON test; AppInstallTest uses a loopback fake HTTP server to prove the POST path and fallback; RemoteStateTest proves all unknown statuses are enabled while Connected and idle. No real TV is contacted by tests.

Earlier implementation evidence: full VERIFY.md fast gate passed at 73c448d for the websocket-primary implementation (ktlint, both flavors unit tests, release lint, all assembles and bundles, androidTest Kotlin compile, node tests, icon check, signing smoke, dk check). Current REST-primary change remains open until the exact fast gate and attended phone check pass. Close only after Netflix, Prime Video, Disney+ and Plex each open on press while Connected during the VERIFY.md attended check.

Attended acceptance 2026-10-30: the owner installed signed release v0.2.3 (tag commit da46a84cabd8569ca254756ef15048a3425c004e) on the phone from the published GitHub Release and reported that the app buttons (Netflix, Prime Video, Disney+, Plex) open on press.
