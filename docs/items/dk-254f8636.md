# Launch app buttons by Samsung app ID; remove calibrated sequences

Owner decision 2026-10-28: replace the per-TV calibrated key sequences with direct app launch by ID, and remove the Calibrate flow and the sequence code (ShortcutProfile/ShortcutStore/ShortcutTextCodec, CalibrationDialog). Record the reversal in docs/DECISIONS.md.

Evidence (read-only GET http://<tv>:8001/api/v2/applications/<id>, 2026-10-28): both household TVs (2020 and 2023 Samsung models) report the apps installed under these IDs: Netflix 3201907018807, Prime Video 3201910019365, Disney+ 3201901017640, Plex 3201512006963. The older IDs 11101200001 and 3201512006785 return 404 on both.

Design: launch over the existing paired websocket (method ms.channel.emit, event ed.apps.launch, data {appId, action_type: DEEP_LINK; NATIVE_LAUNCH for some apps}). REST POST /api/v2/applications/<id> is a fallback only. Grey out a button when the TV reports the app isn't installed (404). No physical launch during automated verification; the owner checks each button on the phone.

Implementation (branch worktree-agent-a4d80f9beca758bca, commit 73c448da6578ea7d0929be1ed51c4a3e1cbb1c01): app buttons send one ms.channel.emit / ed.apps.launch frame (to host, action_type DEEP_LINK) built by SamsungProtocol.launch and queued by KeyDispatcher.launch; never held during recovery, never replayed, dropped by standby if not yet sent. AppInstallClient reads GET :8001/api/v2/applications/<id> on each new session; 404 greys out, anything else stays usable. SamsungProtocol.event no longer treats the TV launch reply (bare data) as a protocol error. Sequence code, CalibrationDialog, Calibrate link and Cancel-sequence row removed; v0.2.0 shortcuts prefs deleted at startup. Evidence: full VERIFY.md fast gate passed at 73c448d (ktlint, both flavors unit tests incl. AppLaunchTest 7/7 and AppInstallTest 4/4, release lint, all assembles and bundles, androidTest Kotlin compile, node tests 15/15, icon check, signing smoke PASS, dk check 0 errors). No TV was contacted. State: implemented and verified offline; not confirmed on a phone. Close only after the VERIFY.md attended app-button check: each button opens its app on each TV.
