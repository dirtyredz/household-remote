# Split theme colour-scheme mapping; give the palette its own home


Source: v0.2.5 push review (componentization and abstraction lenses, 2026-10-30), P2.

ui/theme/RemoteTheme.kt now holds the full Material colour-scheme mapping, RemotePowerRed, shapes, typography and the composable. RemoteTokens also re-aliases RemotePalette fields one-to-one (rockerSurface and ringSurface are both RemotePalette.surface; RemotePowerRed aliases RemotePalette.power). The palette is generated by src/android/icons/generate-icons.mjs from src/android/icons/palette.json, so an app-wide theme concern lives under icons/. The generator emits 13 remote_* colour resources, of which only remote_background and icon_background are read.

Direction: move the colour-scheme mapping into its own file (for example RemoteColorScheme.kt); drop one-to-one aliases until values diverge; give the palette a palette-named home or generator; emit only the resources that XML consumers need.

Acceptance: no visual change; the fast gate and the icon/palette check pass.
