# SSDP discovery finds no TVs on a real phone

Seen 2026-10-26 on v0.1.0 (owner flavor, owner's phone): Discover finds nothing. Adding the TV by IP works end to end (connect, Allow prompt, pairing, keys) on the 2020 parents TV, and SSDP M-SEARCH from a Windows PC on the same LAN finds both Samsung TVs immediately — so network and TVs are fine; the app's discovery path is broken. Discovery was only ever tested against fake servers.

Likely causes, in order: (1) multicast replies dropped — WifiManager.MulticastLock not acquired/held for the receive window, or socket not bound/configured for multicast on the Wi-Fi interface; (2) a missing runtime permission / local-network access on newer Android (targetSdk 36; check NEARBY_WIFI_DEVICES / local network permission behaviour); (3) M-SEARCH sent on the wrong interface or with a too-short receive timeout.

Acceptance: on a real phone on home Wi-Fi, Discover lists both TVs within ~5 s; add a JVM/instrumented test for the multicast-lock lifecycle; record any permission prompt in GOTCHAS. Workaround until fixed: add TVs by IP.
