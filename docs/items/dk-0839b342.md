# provision.ps1 fails parsing op output after storing the key

2026-10-26 real run: both 1Password items were created ('Household Remote signing password' PASSWORD, 'Household Remote signing key' DOCUMENT), then the script stopped with "The property 'id' cannot be found on this object" when reading .id from op JSON (op document create's JSON shape differs). The local key was deleted and the fingerprint not recorded; the orchestrator recovered the fingerprint from the stored document. Fix: parse op output robustly (id/uuid), and make a re-run detect existing items instead of creating duplicates. Also sign-and-publish.ps1 takes -KeyDocument/-PasswordReference IDs — make it resolve by item title so no private IDs need to be kept by hand.
