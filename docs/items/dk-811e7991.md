# Type text on the TV from the phone keyboard


Owner question 2026-10-30: type text on the TV from the phone instead of walking the on-screen keyboard letter by letter.

Feasibility: the Samsung remote websocket (ms.remote.control) accepts a whole string through TypeOfRemote SendInputString, with the text base64-encoded and DataOfCmd base64. The TV emits ms.remote.imeStart and ms.remote.imeEnd events when its on-screen keyboard opens and closes, so the app can show a phone text field only while a TV text box is focused, plus a manual keyboard button as a fallback. Some apps use their own in-app keyboards, which may ignore the IME channel; that needs an attended check on the household TVs.

Acceptance: with the TV keyboard open in a search field (for example Netflix or YouTube), text typed on the phone appears in the TV field, and Enter or Done submits it. Automated tests use fakes only; no keys are sent to a real TV.

Implementation 2026-10-30: phone keyboard dialog opens on current-session IME start or the manual Keyboard button in the navigation row, closes on IME end/dismissal/session or power invalidation, and keeps its draft only in memory. Done submits UTF-8 base64 SendInputString followed by KEY_ENTER as one dispatcher batch; no recovery holding or replay. The dialog lives with overlays under ui/setup without importing ui/remote; the manual Keyboard control lives in NavigationActions. Keyboard visibility is derived from stored intent plus input availability, and losing input clears intent so reconnect cannot reopen a stale dialog. On-Done policy and protocol field shape are documented in DECISIONS.md.

Owner report on installed v0.2.5 (2026-10-30): the phone text box did not open by itself when the TV keyboard was up, so the owner had to tap Keyboard. After typing "honey i shrunk" and pressing Done, only "a" appeared on the TV. Likely cause (suspected, unconfirmed): the TV ignored SendInputString because no IME session was recognised, and the KEY_ENTER that follows pressed the focused key on the TV on-screen keyboard.

Revised owner UX decision (2026-10-30): no input box. Tapping Keyboard, or the TV keyboard opening, brings up the phone soft keyboard directly, and each keystroke goes to the TV immediately as it is typed. Backspace deletes on the TV. There is no Done/submit step, and closing the phone keyboard ends typing. The phone text field must be invisible or minimal, never a dialog.
